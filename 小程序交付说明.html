五、顺带修复的 H5 真实缺陷（2 个 P0）

P0-6：「地图量测 → 保存记录」按钮 100% 崩溃 —— 三重错误叠加
  1. E.GEO.gcjToWgs 方法不存在（正确名 gcj02ToWgs84）→ TypeError
  2. getSit()/getFace() 返回 {lat,lng} 对象而非数组，sit[0] 恒为 undefined
  3. bearing() 是引擎 IIFE 内部函数，UI 作用域不可见 → ReferenceError
P0-7：应用唤醒后磁偏角永不刷新 —— 同一 sit[0]/sit[1] 误用， computeDecl(undefined, undefined) 得到 NaN 后被 isFinite 静默拦掉，无任何报错。
根因反思：181 条引擎断言对 part2.html 的 UI 代码零覆盖，这类「跨文件符号不一致」缺陷没有任何测试能发现。 已新建 tests/ui_static.js（U1–U4）补齐，并把这两个缺陷做成 --selftest 永久夹具。

六、上线 5 步（需你本人操作）

注册小程序账号，拿到 AppID
访问 mp.weixin.qq.com → 立即注册 → 小程序。主体选个人即可满足本工具需求。注册后在「开发 → 开发管理 → 开发设置」复制 wx 开头的 AppID。
名称建议「方位分金罗盘」，简介不要出现「风水」「算命」字样。
安装微信开发者工具
从官方稳定版页下载。安装路径必须纯英文（如 D:\WeChatDevTools）—— 中文路径会导致 CLI 调用、编译缓存、上传出现各种诡异报错。
开启「服务端口」
开发者工具 → 设置 → 安全设置 → 服务端口「开启」。这是自动化的唯一闸门，不开则所有 CLI 命令报 IDE service port disabled。
导入工程并替换 AppID
导入目录 …\2026-08-25-13-38-12\miniprogram，或直接编辑 project.config.json 的 appid 字段（当前为 touristappid）。
导入后先在模拟器核对：盘面能画出来、地图能加载、4 个 Tab 能切换。
真机预览 → 上传 → 提交审核
真机预览必须做：模拟器没有磁力计，方向传感器只能在真机验证。
上传后在「版本管理」提交审核。类目选 工具 → 娱乐；隐私指引必须声明收集位置信息（用途：计算地磁偏角、定位地图中心，仅本机、不上传）。

完整版（含功能说明文案模板、6 类常见驳回原因与应对）见项目根目录 小程序上线操作手册.md。

七、小程序平台踩坑速查

#坑应对
1cover-view 写在 <map> 外面无法覆盖必须是 <map> 的子节点
2cover-view 会吞掉其矩形内的触摸十字准星拆成 3 个细条而非整块容器，否则地图正中央拖不动
3cover-view 对 flex 支持不完整工具列改用逐项绝对定位
4WXSS 不能用本地图片 url()改用 <image>；map marker.iconPath 支持本地文件
5WXML 不支持 HTML 标签<div>/<b>/<span> 全部非法；但 <input>/<button>/<label>/<image> 是真实组件
6文本节点里 \n 不换行拆成多个 <view> 行
7canvas.requestAnimationFrame() 是合法 API写浏览器全局检查时需排除点号前缀，避免误报
8map 的 markers 不支持拖拽事件定向改为「点击地图」+「准星取点」双通道

八、合规要点

微信小程序运营规范禁止「占卜、算命、看风水」类内容。本项目按工具化改造策略处理：

术语中性化（utils/terms.js 唯一出口）

古籍术语对外表述
旺 / 相 / 孤 / 虚 / 空亡主格 / 次格 / 偏格 / 空格 / 骑线
旺相泄囚死（龙脉五行）比和 / 纳音生山 / 山生纳音 / 纳音克山 / 山克纳音
吉 / 凶格位可用 / 格位不宜
大凶方位，避用该方位落在山界线上，建议调整角度

三道硬约束（自检强制执行）

  • C5：40+ 个高风险词（风水、算命、占卜、开光、转运、大师、吉凶…）全工程扫描
  • C5b：业务代码禁止直接读引擎的 r.advice / r.conclusion，必须走 terms.conclusionOf()
  • C10：禁止 wx.request 等联网 API —— 兑现「位置与记录只存本机、零上传」的隐私承诺

类目与隐私

  • 类目：工具 → 娱乐（通用类目最稳）。切勿选任何与命理相关的类目。
  • 隐私指引：必须声明收集「位置信息」，用途写明仅本机计算与存储。
  • 免责声明：每页底部必现（components/disclaimer），关于页有完整版。

九、后续迭代铁律

① utils/engine.js 是生成产物，禁止手改。改引擎请改 assets/part1.html，然后跑 npm run build:mp。
② 新增任何用户可见文案后，必须跑 npm run test:mp（禁词扫描会拦住合规风险）。
③ 新页面必须在 usingComponents 注册 disclaimer 并在 WXML 引用（C6 会拦）。
④ 绝不在 index.html 上直接改代码（H5 的合并产物），只改 assets/part1.html / part2.html 后重新合并。

常用命令

npm run build          # 同步小程序引擎 + 生成图标 + 重合并 H5
npm run test:mp        # 小程序静态自检 C1–C14
npm test               # H5 引擎 181 断言 + UI 跨文件一致性校验
npm run verify         # 全量：构建 + 所有测试 + 双向反向验证
