## 1. 总体架构

### 1.1 架构选型与理由

| 决策点 | 选型 | 理由 |
|--------|------|------|
| 应用形态 | 纯前端单文件 SPA（`index.html`，内联 CSS/JS） | 零后端、零构建依赖、file:// 直开、静态托管即可上线（与「每日运程助手」网页版部署形态一致） |
| UI 框架 | 无框架，原生 JS + Canvas | 体积预算 ≤500KB；罗盘为高频重绘场景，Canvas 直绘性能最优 |
| 罗盘渲染 | Canvas 2D 单画布分层绘制 | 度数环/山环/分金环静态层缓存（离屏 Canvas），仅旋转整体，60fps 可达 |
| 地图 | 自实现轻量 Slippy 瓦片地图（~300 行） | 免密钥、免 SDK；腾讯瓦片 GCJ-02 原生无坐标纠偏负担 |
| 地磁计算 | 内嵌 WMM 球谐模型前端本地计算 | 离线可用、无 API 依赖（决策树见 §5） |
| 测试 | Node 原生 `node:test` + 标记区提取方案 | 引擎纯函数化，单测不依赖浏览器 |

### 1.2 模块分层

```
index.html（单文件）
├── <style> 全部样式（桃橙主题 CSS 变量，主色 #EF7D2D）
├── /*ENGINE-START*/ —— 纯函数引擎区（零 DOM 依赖，测试提取目标）
│   ├── Engine.LUOPAN    度数↔山向↔分金↔兼向↔空亡↔结论
│   ├── Engine.GEOMAG    WMM 磁偏角计算
│   ├── Engine.GEO       坐标转换（WGS84↔GCJ02）、大圆方位角/距离
│   └── Engine.STORE     设置/记录的序列化（纯数据变换，localStorage I/O 由 UI 层注入）
├── /*ENGINE-END*/
└── UI 层（不可单测部分）
    ├── App     Tab 路由、状态管理、权限申请流程
    ├── Compass 传感器采集→平滑→渲染映射，Canvas 绘制
    ├── MapView 瓦片地图、手势、坐向线、拾取
    └── Cards   判读卡/记录页/设置页渲染
```

**关键约束（对应评审 Major-6）**：ENGINE 区不得出现 `document`/`window`/`localStorage` 引用；UI 层只调用引擎函数。测试脚本 `tests/run.js` 以正则提取 ENGINE 区 → `eval` → `node:test` 断言。

## 2. 领域数据模型（判读引擎核心）

### 2.1 二十四山表（地盘正针，磁北 0° = 子山中线）

生成规则：数组按下标 i（0–23），山中线 = i × 15°，山界 = 中线 ±7.5°。

```js
MOUNTAINS = ["子","癸","丑","艮","寅","甲","卯","乙","辰","巽","巳",
             "丙","午","丁","未","坤","申","庚","酉","辛","戌","乾","亥","壬"]
// 顺时针序，i=0 → 子(0°)，i=1 → 癸(15°) …… i=23 → 壬(345°)
```

八卦分区（卦界即大空亡线，共 8 条）：

| 卦 | 三山 | 度数域 |
|----|------|--------|
| 坎 | 壬子癸 | 337.5°–22.5° |
| 艮 | 丑艮寅 | 22.5°–67.5° |
| 震 | 甲卯乙 | 67.5°–112.5° |
| 巽 | 辰巽巳 | 112.5°–157.5° |
| 离 | 丙午丁 | 157.5°–202.5° |
| 坤 | 未坤申 | 202.5°–247.5° |
| 兑 | 庚酉辛 | 247.5°–292.5° |
| 乾 | 戌乾亥 | 292.5°–337.5° |

### 2.2 一百二十分金全表生成规则（评审 Major-4 决议）

**规则三要素**（代码按此生成 120 格，非硬编码表）：

1. **支归属**：每一山取「顺时针方向其后最近的地支山」之支。
   - 地支山取本支（子山→子，丑山→丑……）；
   - 干维山取前方地支（癸山→丑，艮山→寅，甲山→卯，乙山→辰，巽山→巳，丙山→午，丁山→未，坤山→申，庚山→酉，辛山→戌，乾山→亥，壬山→子）。
   - 推论：每个干支在全盘出现恰 2 次（本支山 1 次 + 前方干维山 1 次），60×2=120 ✓。
2. **干序**：支为阳（子寅辰午申戌）→ 干序 `甲丙戊庚壬`；支为阴（丑卯巳未酉亥）→ 干序 `乙丁己辛癸`。按度数增大方向排列，每格 3°。
3. **居中律**：每山第 3 格（正中 ±1.5°）恒为戊X（阳支山）或己X（阴支山），即「正针」。

**标准锚点校验集**（单测必须锁定，防生成规则漂移）：

| 锚点 | 期望 |
|------|------|
| 子山（352.5°→7.5°）五格 | 甲子、丙子、戊子、庚子、壬子；戊子居 358.5°–361.5° |
| 丑山（22.5°→37.5°）五格 | 乙丑、丁丑、己丑、辛丑、癸丑；己丑居中 30° |
| 壬山五格 | 甲子、丙子、戊子、庚子、壬子（337.5° 起） |
| 艮山五格 | 甲寅、丙寅、戊寅、庚寅、壬寅（借寅支，37.5° 起） |
| 癸山五格 | 乙丑、丁丑、己丑、辛丑、癸丑（借丑支，7.5° 起） |
| 亥山五格 | 乙亥、丁亥、己亥、辛亥、癸亥（292.5°…亥山中线 330°，己亥居中） |
| 全盘 | 120 格各 3° 无缝隙无重叠；60 干支各出现 2 次 |

### 2.3 分金属性（孤虚旺相）

按分金干支之**天干**判定（设置不可改）：

| 天干 | 属性 | 可用性 |
|------|------|--------|
| 丙、庚 | 旺 | ✅ 可用 |
| 丁、辛 | 相 | ✅ 可用 |
| 甲、壬 | 孤 | ❌ 不可用 |
| 乙、癸 | 虚 | ❌ 不可用 |
| 戊、己 | 空亡 | ❌ 不可用（正针格） |

### 2.4 二百四十分金

每山 10 格各 1.5°：将 120 分金每格二分，沿用同一干支（盘面以格线密度区分）。山向结论不受粒度影响（AC21）。

### 2.5 兼向与空亡算法（评审 D-1 决议精确化）

输入：磁北度数 d（0–360）、空亡判定宽度 w（默认 1.5°，设置项 0.5/1/1.5）。

```
1. 山界集 B = { 7.5 + 15k, k=0..23 }；对每 b∈B：若 |d−b|（圆距）≤ w：
     若 b ∈ 卦界集 {22.5,67.5,...,337.5} → 告警「大空亡」
     否则 → 告警「小空亡（骑线）」
2. 本山 m = 度数所落山；偏角 off = 圆距(d, 山中线)（0–7.5°），偏向侧 s = 相邻山
3. 兼向表述：
     off ≤ 1.5°        → 「正向」
     1.5° < off ≤ 4.5° → 「X山兼S山N分」，N = round(off/1.5)，N∈{1,2,3}
     off > 4.5°        → 「X山兼S山过重（偏off°）」
4. 输出对象 LuopanReading {
     degree, mountain, sittingMountain(对宫山), facingMountain(本山按语义区分),
     offsetDeg, jianLabel, fenjinGanZhi, fenjinAttr, kongwang:{type|null, lineDeg},
     conclusion(六要素字符串) }
```

> 语义约定：手机指向/坐向线终点方向为「向」，向山 = d 所落山；坐山 = 对宫（d+180° 所落山）。

## 3. 地磁模型（GEOMAG 模块）

### 3.1 算法

世界地磁模型 WMM：球谐展开至 12 阶，Schmidt 半归一化勒让德函数，输入大地坐标（WGS-84 椭球高 h≈0）与十进制年，输出磁偏角 D（度，东偏为正）。

```
D = atan2(Y, X)（东偏为正；罗盘修正：磁北方位角 = 真北方位角 − D）
```

### 3.2 系数获取决策树（评审 Major-3）

```
开发期获取系数：
  ① 首选：NOAA/NCEI WMM2025 COF 文件（官方源）→ 嵌入 GEOMAG.COEFFS
  ② 若网络不可达：使用已发表 WMM2020 COF（含长期变化项 SV，外推至 2026，
     中国区域磁偏角漂移 <0.1°/年，误差仍在 0.5° 预算内）→ 界面标注模型年份
  ③ 禁止：凭记忆手写系数（精度不可验证）
运行期：
  纯前端计算，输入 WGS-84 坐标（GCJ-02 拾取点先经 §4.1 逆变换，坐标误差对 D 影响 <0.01°，可忽略）
```

### 3.3 精度预算

| 误差源 | 量级 |
|--------|------|
| WMM 模型本身（2025 纪元内） | ≤0.3°（中低纬） |
| 系数外推（若走 ② 分支） | ≤0.2° |
| 局部磁异常（不可建模） | 未计入，界面披露 |
| **合计** | **≤0.5°，满足 AC05** |

## 4. 地理计算（GEO 模块）

### 4.1 坐标转换

- WGS-84 ↔ GCJ-02：国家标准加密算法的通用公开近似实现（克拉索夫斯基椭球 a=6378245，偏心率平方 ee=0.006693421622965943），双向转换（逆向采用迭代逼近，2 次迭代残差 <1e-9°）。
- GPS 定位结果（WGS-84）→ 转 GCJ-02 后用于地图落点；地图拾取点（GCJ-02）→ 逆变换 WGS-84 后用于磁偏角计算。
- 已知点对照测试：北京天安门（WGS 39.9087,116.3975）→ GCJ ≈ (39.90733, 116.40342)？以标准实现输出为准做回归锁定（误差 ≤1e-6° 自一致 + 与公开参考值偏差 ≤0.001°）。

### 4.2 方位角与距离

- 大圆初始方位角：θ = atan2(sin Δλ·cos φ₂, cos φ₁·sin φ₂ − sin φ₁·cos φ₂·cos Δλ)，输出 0–360°（真北基准）。
- 距离：Haversine（R=6371008.8m），仅展示用，精度要求 ±1%。
- 向→坐取 bearing(向点→坐点)；坐 = 向 + 180°（圆回取模）。线中点坐标用于磁偏角计算。

## 5. 传感器链（Compass 模块，评审 Major-2）

```
DeviceOrientation 提供链（优先级从高到低）：
L1 Android/新版：'deviceorientationabsolute' 事件
    heading = (360 − event.alpha) % 360     // absolute alpha，0=北
L2 iOS：DeviceOrientationEvent.requestPermission() 授权后 'deviceorientation'
    事件含 webkitCompassHeading → heading = event.webkitCompassHeading
L3 兜底：'deviceorientation' 相对 alpha + 手动校零按钮（「以当前朝向为0°」）
    → 界面黄条明示「相对方位模式，仅供参考」
L0 全部不可用/被拒 → 引导切换地图模式（完整替代路径）
```

- **平滑**：一阶低通滤波 α=0.15 + 角度环回差值处理（跨 0/360 时取最短弧插值），消除抖动。
- **精度事件**：`event.absolute===false`（L3）或 webkitCompassAccuracy > 15° → 触发干扰黄条（AC20）。
- **渲染映射**：纯函数 `mapSensorToDial(heading)` → 盘面旋转角 = −heading（盘转针定式），单测锁定（AC02）。

## 6. 瓦片地图（MapView 模块，评审 Major-1）

### 6.1 瓦片源

| 项 | 值 |
|----|-----|
| 默认源 | 腾讯栅格瓦片 `https://s{s}.map.gtimg.com/realtimerender?z={z}&x={x}&y={-y}&style=0&l=3`，s∈[0,3]，GCJ-02 坐标系（拾取点无需纠偏） |
| 降级源 | 无瓦片网格底图（Canvas 绘制经纬网格 + 比例尺），量测功能完整保留 |
| 触发 | 单瓦片源连续 4 张失败 → 自动降级 + 黄条提示 |
| 缩放域 | z ∈ [3, 18] |

### 6.2 手势与交互

- 拖动（单指）、双指缩放（捏合中心锚定）、双击放大；`touch-action:none` + passive:false 阻断默认。
- 长按 500ms → 十字准星选点（吸附加强：选点即「坐点」）。
- 坐向线：坐点（钉）→ 可拖终点（柄）；线实时重算判读（节流 50ms）。
- 拾取坐标显示格式随设置（度 / 度分秒）。

### 6.3 合规

仅使用审图号底图服务；页面页脚与判读卡双免责声明；不提供境外瓦片切换。

## 7. 前端状态与持久化

```ts
Settings  { fenjinMode: '120'|'240', kongwangWidth: 0.5|1|1.5,
            coordFormat: 'deg'|'dms', trueNorthMode: bool, dialStyle: 'modern'|'classic' }
Record    { id, ts, mode:'live'|'map', lat, lng, decl, degTrue, degMag,
            reading: LuopanReading(JSON), note? }   // FIFO 上限 50
localStorage keys: 'lp_settings', 'lp_records', 'lp_decl_cache'{lat,lng,decl,ts}
```

引擎 STORE 模块只做纯数据变换（默认值合并、入队 FIFO、序列化校验），localStorage 读写由 UI 层调用注入，保证可测性。
