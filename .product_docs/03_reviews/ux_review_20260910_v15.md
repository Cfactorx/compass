## 二、P0 缺陷（立即修复，可信度与跨模式一致性问题）

### P0-1【可信度打击】实地/地图判读卡"params"面板默认状态不一致
- **位置**：index.html:597（实地，`<details>` 无 `open`） vs index.html:978（地图，`<details class="params" open>`）
- **现状**：实地罗盘首屏打开，专业参数（分金格/偏出/空亡依据）默认折叠；地图模式默认展开
- **影响**：实地罗盘用户（最专业的人群）必须多点一下才能看到关键判读依据，地图用户却一眼看到全部——**反向暗示"实地模式不如地图准"**，对玄学用户是可信度打击
- **建议方向**：index.html:597 改为 `<details class="params" open>`，与地图同节奏

### P0-2【认知负担】地图无方向箭头 + 长按提示文案模糊
- **位置**：index.html:806-834（drawOverlay） + index.html:181（mapHint）
- **现状**：地图只画了坐点（红圆+白"坐"字）、向点（橙圆+旁"向"字）、虚线，**无方向箭头**；mapHint 写"长按地图选坐点，拖手柄定向"
- **影响**：40+ 用户最怕"按错按钮重测一遍"；从实地罗盘切到地图的人，习惯"罗盘盘子转到某个山朝我"，看到两条圆点+虚线会问"我点的是坐还是向？"
- **建议方向**：虚线中点加 `▶` 三角箭头朝 facePt；mapHint 改为两行 `<b>长按地图</b>选「坐」点，再拖<b>橙圆</b>定「向」`；橙圆加"drag me"动效（呼吸缩放）

### P0-3【数据可信度】旧 V1.0 pan 模式记录无迁移/降级
- **位置**：index.html:1047（`{live:'实地罗盘', map:'地图量测', pan:'手工排盘'}`） + 1023（saveRecord 仅接受 live/map）
- **现状**：保存函数已无 `pan` 写入路径，但 `renderRecords` 仍把 `mode==='pan'` 渲染为"手工排盘"标签
- **影响**：V1.0→V1.4 老用户翻记录看到"手工排盘"以为还有这个功能→找不到入口→以为 App 烂尾。**玄学用户对"记录丢失/数据真伪"极敏感**
- **建议方向**：`renderRecords()` 顶部加一次性 migrate：`list.filter(it=>it.mode!=='pan').map(...)` + 在空态文案下加 `提示：1.4 起「手工排盘」已合并到「地图量测」，旧记录已自动归类`

### P0-4【架构债】settings 持久化无 schemaVersion，字段漂移无审计
- **位置**：index.html:209（state 初化） + 1497（`E.STORE.mergeSettings`）
- **现状**：`lp_settings` 直接以裸 JSON 持久化，mergeSettings 用白名单 + fallthrough，**未知 key 静默丢弃**
- **影响**：未来 2-3 个版本后，无法定位"为什么老用户设置不生效" / 为什么某条旧记录渲染异常
- **建议方向**：DEFAULTS 加 `schemaVersion: 1`，mergeSettings 末尾写入 ts；下次变更先 `localStorage.removeItem('lp_settings_v0')`

### P0-5【崩溃路径】localStorage 不可用 → 整页白屏
- **位置**：index.html:208-215（state 初化）
- **现状**：`settings: E.STORE.mergeSettings(E.STORE.safeParse(localStorage.getItem('lp_settings'), {}))` **外层无 try/catch**。Safari 私密浏览模式 100% 抛 `QuotaExceededError` → IIFE 启动失败 → 白屏
- **影响**：用 Safari 隐私模式（iOS 默认支持）的用户**首次打开即白屏**，且无任何降级
- **建议方向**：208-215 行包 try/catch，catch 时 `var state = { settings: E.STORE.mergeSettings({}), ... }` + 顶部 chip toast "隐私模式：本次配置不保存"

### P0-6【可感知 Bug】真北模式开关切换后无反馈，用户需晃动手机才生效
- **位置**：index.html:1110（`swTrueNorth` 点击）+ 1123（`applySettings`）+ 575（`maybeUpdateLiveCard`）
- **现状**：开关 → applySettings → buildDial() + `state.lastCardDeg = null`（关键）。但 applySettings **只在 mapView.getSit() 时调 onLineChange**，实地罗盘不调——开关切换要等 heading 变化 >0.2° 才更新盘面
- **影响**：用户切开关后看到"没反应"，体感是 bug，会反复点开关甚至怀疑应用坏了
- **建议方向**：applySettings 末尾追加 `if (state.hasHeading) renderLiveCard(effFacing());`，保证开关态映射到下一次绘制

## 三、P1 风险（近期整改，核心体验）

### P1-1【空亡/凶视觉等同】玄学用户分不清"空亡"与"犯凶"
- **位置**：index.html:586-587（实地）、964-965（地图）；CSS index.html:59-60（`.tag.ok/.tag.bad`）
- **现状**：`kongwang ? 'bad' : (r.usable ? 'ok' : 'bad')` —— 空亡和普通凶都红底，**没有"最严重等级"标识**
- **影响**：玄学用户眼里"空亡"是坐线落到山界上（最不能下葬），但视觉等同"犯孤/虚"，容易误判
- **建议**：CSS 加 `.tag.severe`（黑底白字+⚠️）+ kongwang 分支 map 到 'severe'，tagTxt 前缀"⚠️ 空亡·"

### P1-2【玄学可信度】品牌区缺师承/出处叙事
- **位置**：index.html:146（brand）
- **现状**：品牌区只有"罗盘分金 --powered by 吕庆新"；真正的可信度素材（地盘正针、三合盘、纳音五行、WMM2025）藏在设置页最底下一行 12px 灰字
- **影响**：玄学用户最在意"出处/师承"，但首屏看不到任何关于"为什么这个判读值得信"的信号
- **建议**：brand 改两行，第二行 11px 浅色字 `三合盘 · 二十四山 · 纳音五行 · powered by 吕庆新`

### P1-3【一致性遗留】真北模式两模式展示口径不同
- **位置**：index.html:593（实地，单 chip） vs index.html:971-972（地图，双 chip）
- **现状**：实地只显示"当前生效值"，地图同时显示真北+磁北+磁偏角三个 span
- **影响**：用户开真北模式在实地看到"真北 175.3°"，切到地图又看到"真北 175.3° + 磁北 178.6°"——会以为判读结果不同
- **建议**：index.html:593 改与 971-972 对齐（双 chip）

### P1-4【死设置】空亡判定宽度开关对老用户无感知
- **位置**：index.html:1081-1082（设置项） + 罗盘盘面 index.html:282-500（无空亡视觉层）
- **现状**：开关改 kongwangWidth 立即影响判读，但盘面**没有任何"空亡环"高亮**（仅高亮旺相/孤虚）
- **影响**：用户改 ±0.5° vs ±1.5° 无感知，下次测量判读突然"凶了"——以为是 bug
- **建议**：盘面 attr==='空亡' 区域加更深灰底 + 设置副标说明"切换后请重新测量一次以确认"

### P1-5【地图交互】双指 pinch 第一帧延迟 + 跨指"幽灵"指针
- **位置**：index.html:849-898（pointer 事件链）
- **现状**：pinchDist 起步为 0，要滑动 0.8×/1.25× 才有反应；pointers 字典留有上一指的"幽灵"导致 dx/dy 跳跃
- **影响**：双指缩放前几次延迟；切回单指时可能触发意外拖动
- **建议**：pinchDist 立即初始化为两指当前距离；pointerup 时清干净

### P1-6【iOS 降级】传感器权限被永久拒绝后 listener 残留
- **位置**：index.html:665-700（initSensor、permSkip）
- **现状**：permSkip 后 onSensorEvent 仍挂在 window 上，state.hasHeading 不更新
- **影响**：iOS 用户点"暂不开启"后回到 live 罗盘，指针用上一次 heading 不动
- **建议**：permSkip 后 `removeEventListener('deviceorientation', onSensorEvent)` + `state.hasHeading=false`

### P1-7【后台/唤醒】罗盘卡住或乱跳
- **位置**：index.html:555-563（animLoop）
- **现状**：无 `visibilitychange` 处理；后台→前台时 sensor 一次性吐累积误差，headingSm 0.22*delta 跨 0°/360° 会瞬间指反
- **影响**：手机休眠唤醒后罗盘乱跳
- **建议**：监听 visibilitychange，visible 时 headingSm=heading 重启 + 对 |delta|>60° 降权警告

## 七、测试覆盖盲点（建议补强）

当前 tests/run.js 跑 174 个**纯函数**测试，**未覆盖**：
- 传感器事件链（onSensorEvent）
- 判读卡渲染（renderLiveCard / renderMapCard）
- 地图交互（pointer 事件链、setSit、onLineChange）
- localStorage 异常路径（QuotaExceededError、隐私模式）
- 模式切换副作用（switchTab、applySettings）

**建议下一步**：补一个 pupeteer/playwright 端到端冒烟脚本（场景：定位失败→手动 fallback→切到地图→长按设点→保存记录→离线 reload），覆盖关键 UI 交互与错误恢复路径。
