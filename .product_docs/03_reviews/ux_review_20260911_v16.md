## 二、P0 缺陷（4 条，建议 V1.6 立即打）

### P0-1【架构性 vs 补丁性】`.coord-input-row` 仍嵌在 `#mapArea` 内，V1.5.2 是补丁不是根治
- **位置**：index.html:190-194（DOM 嵌套）+ 1333/1363（area early-return selector）+ 1507-1513（逐元素 stopPropagation）
- **现状**：经纬度输入框本不该在地图手势容器内。V1.5.2 加了 `closest('input, button, select, textarea, .coord-input-row, .map-tools')` 防御 + 3 处 stopPropagation 补丁，但**未来加任何新交互控件**（导出/分享/收藏）都需手动加 selector + stopPropagation，漏一处即阻断 focus
- **影响**：V2.0 必踩坑，每次新增按钮都要"打补丁式"修；架构债随功能增长滚雪球
- **建议方向**（根治）：
  1. 把 `.coord-input-row`（及 `.map-tools`）从 `#mapArea` 内部**移出**，作为 `#view-map` 的兄弟节点（用 position:absolute 覆盖）
  2. 引入 `data-map-ignore` class 统一标记交互控件，area early-return 改为 `if(ev.target.closest('[data-map-ignore]')) return;`
  3. 新增交互控件只需加 `data-map-ignore` class 即自动豁免

### P0-2【首屏可见性】`P0-5` 修复有缺口：Safari 隐私模式首屏仍无任何提示
- **位置**：index.html:676-695（catch 仅置 `_noStorage` 标记，未立即 toast）+ 704/1538（toast 仅在保存/设置时触发）
- **现状**：V1.5 P0-5 让白屏不再发生，但 catch 块只设标记，**首屏渲染早于任何提示**——Safari 隐私模式用户看不到"配置不保存"
- **影响**：用户以为设置生效，下次刷新丢失，**对玄学应用用户是"数据失真"敏感事件**
- **建议方向**：在 state 初化 try/catch 末尾、UI IIFE 启动第一帧时，检测 `if(state._noStorage) toast('隐私模式：本次配置不保存', 4000)`

### P0-3【数据可信度】pan 旧记录迁移提示只放在记录页内，首屏看不见
- **位置**：index.html:1544-1556（`renderRecords` 内的横幅）
- **现状**：V1.5 P0-3 让 pan 旧记录自动迁移为 map，**但迁移提示横幅只在用户主动打开"记录"页才显示**——首屏 / 实地罗盘 / 地图量测三个 Tab 都没有任何"手工排盘已合并"信号
- **影响**：40+ 用户切回首屏可能仍以为"手工排盘"功能在、到处找入口
- **建议方向**：在设置页 `dialStyle` 组上方加一行**常驻浅橙说明**："V1.4 起「手工排盘」已合并到「地图量测」"，不依赖打开记录页

### P0-4【真 bug】传感器 `alpha=NaN` 会永久冻结罗盘
- **位置**：index.html:1128（绝对分支）+ 1139（相对分支）
- **现状**：三分支仅判断 `e.alpha != null`，**未用 `isNaN` 守卫**。`alpha=NaN` 经 `E.norm` 得 NaN → `headingSm` 永久 NaN → 盘面停转、badge 显示 `NaN°`、判读卡停止刷新
- **影响**：iOS/Android 瞬时 NaN 上报即**永久冻结**整个实地罗盘，只能重开 App。玄学用户多次遇到会以为"应用坏了"
- **建议方向**：三分支统一加 `isNaN(e.alpha)` 守卫，丢弃 NaN 数据不更新 heading

## 三、P1 风险（6 条，建议近期整改）

### P1-1【构建工程债】合并靠 `node -e` 临时脚本，未固化为 scripts/merge.js
- **位置**：全局（无 `scripts/merge.js`、无 `package.json`、无 `build:merge` script；合并契约仅 MEMORY.md:20-29 散文描述）
- **现状**：V1.5.1 已修复合并错位，但"工作流约定"是写在 MEMORY.md 散文里——下一个开发者不知道，会再次踩坑
- **影响**：下次合并若切分位置写错即重演"P0 修复全丢 + 合并错位"双重灾难
- **建议方向**：建 `scripts/merge.js`——
  1. 读 part1/part2
  2. 校验 ① `/*ENGINE-START*/` 存在 ② part1 末尾含 `</script></body></html>` ③ part2 末尾无收尾
  3. 用 `new Function` 校验各 script 块语法
  4. 写后做 HTML 标签平衡检查
  5. 加 `npm run build:merge` + git pre-commit hook

### P1-2【静默白屏】ENGINE 加载失败 + 无 `window.onerror`，最深层崩溃无护栏
- **位置**：index.html:671 `var E = LP;`（在 try 外）vs 676 的 try/catch
- **现状**：V1.5 P0-5 兜底的是 `localStorage` 抛错。但若 ENGINE IIFE 本身执行异常（哪怕一个笔误），`LP=undefined` → 671 行抛 ReferenceError → IIFE 直接崩溃，676 的 catch 根本进不去；且全文无 `window.onerror`
- **影响**：比 P0-5 设想的更严重——**任意脚本笔误即整页白屏，无任何降级提示**
- **建议方向**：① IIFE 最外层包宽 try/catch ② index.html 末尾加 `window.onerror=function(){document.body.innerHTML='加载失败，请刷新'}` ③ `E` 取值前 `if(!LP||!LP.STORE)` 降级到内联默认 settings

### P1-3【性能】地图拖动时每帧 renderTiles 全量重排 50+ 瓦片
- **位置**：index.html:1381-1391 `pointermove` 每次调 `renderTiles()`+`drawOverlay()`
- **现状**：renderTiles 对 50+ 可见 tile 逐张 `positionTile` 改 style/DOM；drawOverlay 画线/箭头/圆点。连续拖动主线程卡顿
- **影响**：iOS Safari 60Hz sensor 拖动时主线程占用 30-50ms/帧，明显卡顿
- **建议方向**：拖动中只调 `drawOverlay()`（overlay 是独立 canvas），松手/缩放时才 `renderTiles`；或 rAF 合帧

### P1-4【交互断点】`pointerleave` 会提前结束地图拖动
- **位置**：index.html:1402 `area.addEventListener('pointerleave', endPointer)`
- **现状**：拖动中手指滑出 area 边界即 `endPointer` → `dragging=null`，平移中断
- **影响**：手指靠近地图边缘拖不动，体感断裂
- **建议方向**：删除 `pointerleave` 监听，改用 `setPointerCapture` 或仅保留 `pointerup/cancel`

### P1-5【空亡/凶视觉等同】玄学用户分不清"压山界大凶"与"犯孤虚"
- **位置**：index.html:1066-1067 `tagCls = r.kongwang ? 'bad' : (r.usable ? 'ok' : 'bad')`
- **现状**：空亡与普通凶同红底 `.tag.bad`
- **影响**：玄学用户眼里"空亡"是坐线落到山界上（**最严重等级**），但视觉等同"犯孤/虚"，容易误判"还能用"
- **建议方向**：CSS 加 `.tag.severe`（黑底白字+⚠️），kongwang 分支 map 到 severe，tagTxt 前缀"⚠️ 空亡·"

### P1-6【后台/唤醒】罗盘无 visibilitychange 监听，跨 0/360° 瞬跳
- **位置**：全文 grep 无 `visibilitychange`
- **现状**：手机休眠唤醒后 sensor 一次性吐累积误差，headingSm 跨 0/360° 瞬跳
- **影响**：后台→前台时罗盘乱跳几秒
- **建议方向**：监听 `visibilitychange`，visible 时 `headingSm=heading` 重启；`|delta|>60°` 降权警告
